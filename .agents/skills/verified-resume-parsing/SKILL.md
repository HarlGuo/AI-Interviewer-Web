# 可验证简历解析

以源文本为唯一事实依据。任一步校验失败时，必须明确报错或降级为仅规则解析，不得标记为“AI 已验证”。流程如下：

1. **确定性提取**：校验类型和大小；用格式适配的解析器提取文本；执行 Unicode NFKC 规范化并保留原始行序；按明确规则分段。PDF 还须检查页面渲染；无可用文本层时要求 OCR，不得宣称成功。
2. **AI 分类**：脱敏电话、邮箱、地址、证件号等字段；为文本行分配 `L001` 等稳定 ID；仅让模型返回行到允许章节的归类及风险，不得改写、概括、增删或推断事实。
3. **程序校验**：确认每个输入 ID 恰好出现一次、无未知 ID、章节合法、顺序不变，并仅用原始行重建。失败时返回明确错误或标注为仅规则解析，不得标记为 AI 已验证。
4. **用户确认**：展示重建章节、警告和复核问题；用户确认或替换简历后，才能用于个性化面试。不得承诺零错误，用户拥有最终确认权。

实现或修改解析器、协议或测试时，读取[解析契约](references/contract.md)。

## 安全要求

- 不提交或记录真实简历、个人身份信息、API Key、授权头及模型载荷。
- 私有测试简历放入 Git 忽略目录；模型密钥仅存于后端机密环境。
- 模型只接收复核必需的最少脱敏内容。

## 验收

测试非法类型、超限文件、空白/扫描 PDF，以及 AI 遗漏、重复、未知 ID、非法章节；用已授权真实简历做本地测试但不提交；确认 Git 忽略私密材料，且界面区分确定性提取、AI 验证与用户确认。

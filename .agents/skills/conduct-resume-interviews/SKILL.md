# 简历驱动的动态面试

仅使用通过 `$verified-resume-parsing` 且由用户确认的简历。简历、职位描述和用户回答是唯一证据，不得编造候选人事实。

1. **开始**：要求已确认简历和非空目标岗位；移除联系方式及无关信息；按模式确定阶段；依据当前阶段和具体简历/职位证据生成问题。每轮只返回一道问题，并保存可恢复状态。
2. **评估**：检查回答是否笼统、缺少案例、个人贡献或量化结果，未解释方案，与既有证据冲突，或含值得深挖的细节。只返回 `follow_up`、`next_main`、`complete` 之一。
3. **追问**：每道主问题最多两次；追问必须基于最新回答。回答充分则推进；用户明确“不知道”则记录薄弱点并推进；到达上限后覆盖模型的继续追问决定。
4. **控制**：模型仅提出判断和问题；确定性程序控制计数器、动作、阶段、必填字段和完成条件，并拒绝空白、畸形或违约输出。未建立身份验证的服务端持久化前，每轮传递所需状态；API Key 不得进入客户端。
5. **报告**：只用已确认岗位上下文和提交的回答。每项评分包含理由、回答证据及可执行建议；无依据时标记 `证据不足`。无摄像头数据时，不预测 Offer 或评价肢体语言。

实现或修改顺序、提示词、数据结构或测试时，读取[面试状态机](references/state-machine.md)。

## 验收

测试个性化首题、各类追问触发、充分回答推进、`follow_up_count = 2` 强制推进、“不知道”不反复施压、错误 JSON 安全失败，以及未确认简历无法开始。用已授权真实简历做端到端测试，但不提交个人信息或模型载荷。

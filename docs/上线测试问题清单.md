### 001 上线版本仍向用户展示内部提示性文案

**发现位置**

- 正式模拟面试页：题目卡片内或题目下方展示的后端生成提示，例如截图中的“相关经历：曾担任产品实习生，并参与产出产品体验报告、竞品分析、产品原型图”。
- 面试开始时：第一题附带的提示性内容。
- 登录相关页面或流程：类似“审核不消耗面试次数”的内部说明或测试提示。
- 首页、个人中心或数据相关页面：类似“简历、回答和报告的云端同步将在 Supabase 项目创建并执行数据库迁移后启用。当前设备缓存已经按账号隔离”的技术实现与开发进度说明。

**当前问题**

这些内容属于辅助生成、审核或测试阶段使用的提示信息。上线后直接展示给用户，会暴露内部处理逻辑，也会对用户回答形成额外引导，影响正式面试体验。

**期望结果**

- 正式上线版本不展示上述内部提示性文案。
- 面试页只展示用户完成面试所必需的正式内容，包括题目、进度、回答区域和正式操作控件。
- 第一题与后续题目的展示规则一致，不因题目序号额外显示内部提示。
- 登录流程不展示“审核不消耗面试次数”等仅供内部测试或审核使用的说明。
- 不向用户展示 Supabase、数据库迁移、设备缓存、账号隔离实现方式等技术说明或开发状态。
- 如相关提示仍需用于后端生成、审核或调试，可在内部保留，但不得出现在面向用户的上线界面中。

**范围说明**

- 本问题只要求隐藏内部提示，不要求修改正式面试题正文。
- 不删除或改写用户必须知晓的正式规则、隐私授权、错误提示和计费/次数变化结果。
- 对性质不明确的文案，修改前先确认其是否属于用户必须知晓的信息，不能直接批量删除。

**验收标准**

1. 正式模拟面试进入第一题后，不出现后端生成的“相关经历”等答题提示。
2. 切换至后续题目后，同样不出现任何内部生成提示、参考答案方向或调试说明。
3. 登录及相关审核流程中，不出现“审核不消耗面试次数”等内部测试提示。
4. 面向用户的页面中，不出现 Supabase 项目创建、数据库迁移、设备缓存或账号隔离实现方式等内部技术信息。
5. 隐藏上述内容后，题目正文、题目进度、语音回答、文字回答、暂停和结束等正式功能仍可正常使用。
6. 用户必须知晓的正式业务规则和异常提示仍正常展示；如果云端同步尚不可用，只能以用户能理解的产品状态说明，不暴露供应商或工程实现细节。

**参考截图**

- 用户提供的上线测试截图：正式模拟面试页中，题目正文下方显示蓝底“相关经历”提示。
- 用户提供的上线测试截图：首页或数据相关区域显示 Supabase、数据库迁移、设备缓存和账号隔离说明。

**处理状态**

- 已移除面试问题依据、首题生成说明、审核次数说明、云端技术实现说明及其他测试版本标识。
- 已通过文案检索、TypeScript、ESLint、Expo Doctor 与 Web 生产构建检查。

### 002 面试报告返回首页后无法再次查看

**发现路径**

1. 用户完成一次正式模拟面试。
2. 系统成功生成并展示面试报告。
3. 用户点击“返回首页”。
4. 用户再次尝试查看本次面试记录或报告时，页面显示“没有可用的面试记录”，只提供“返回首页”按钮。

**当前问题**

报告只能在刚生成时查看，离开报告页后没有可靠的再次访问入口。用户无法回看回答、评分依据和改进建议，也就无法完成面试复盘。当前尚不能确认是报告数据未保存、记录查询失败，还是首页缺少历史记录入口；实施修改前需要定位实际原因，不能直接假设报告已经丢失。

**用户目标**

- 完成面试并生成报告后，用户可以随时从首页或明确的历史记录入口重新打开该报告。
- 用户可以依靠历史报告进行复盘，而不是只能在报告首次生成时查看一次。

**期望结果**

- 报告生成成功后，本次面试及其报告应成为可再次访问的历史记录。
- 首页应提供清晰的“面试记录”或“历史报告”入口；如果首页已有该入口，则应能正确展示已完成的面试。
- 历史记录至少应帮助用户识别面试时间、目标岗位和完成状态，并可进入对应报告。
- 重新进入报告后，应展示与首次生成时一致的正式报告内容，包括评分、评分理由、来自用户已确认回答的证据以及可执行建议；证据不足的项目仍须明确标注，不能补猜内容。
- 用户正常退出报告页、返回首页或重新打开 App 后，已成功生成的报告不应消失。

**异常与边界**

- 报告仍在生成时，应展示明确的生成中状态，不能误报“没有可用的面试记录”。
- 报告生成失败时，应说明失败状态并提供安全的重试方式，不能创建一条看似完成但无法打开的记录。
- 未登录用户、跨设备查看和历史记录保留期限是否支持，当前待确认；在定位现有账号及云端保存规则后再确定范围。
- 如果确实没有任何已完成记录，才展示空状态；空状态应与“记录加载失败”区分。

**验收标准**

1. 完成面试并成功生成报告后，点击“返回首页”不会导致本次报告不可访问。
2. 用户可通过首页的明确入口找到刚完成的面试记录，并重新打开对应报告。
3. 关闭并重新打开 App 后，在现有账号与数据保存规则允许的范围内，已生成报告仍可访问。
4. 历史报告内容与首次生成结果一致，不重新编造或改变评分、理由、回答证据和建议。
5. 加载中、生成失败、记录为空和网络错误分别显示与真实状态一致的反馈。
6. 不再出现“报告已经生成并查看过，但返回首页后显示没有可用的面试记录”的情况。

**参考截图**

- 用户提供的上线测试截图：离开已生成的报告后再次访问，页面显示“没有可用的面试记录”和“返回首页”按钮。

**处理状态**

- 已实现本机报告历史保存，返回首页时不再删除已生成的报告记录。
- 已实现登录账号从云端读取已生成报告，并增加首页、底部导航和个人页的“面试复盘”入口及历史列表页。
- 已通过浏览器导航、空态、控制台错误、TypeScript、ESLint、Expo Doctor、Web 生产构建与后端测试检查。

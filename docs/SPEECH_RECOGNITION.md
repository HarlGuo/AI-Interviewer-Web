# 语音转文字

## 当前方案

App 通过 `expo-speech-recognition` 调用 iOS Speech framework 和 Android SpeechRecognizer，不接入按量计费的第三方转写 API。支持时优先要求设备端中文识别；不支持时由操作系统提供联网识别，具体数据处理受设备系统和默认语音服务约束。

主流程为：用户点击“开始语音回答” → 申请权限 → 系统持续识别 → 用户明确点击“结束回答并自动提交” → 最终转写自动提交给面试 Agent。短暂停顿只会触发继续聆听，不会提交。文字框用于实时查看、必要修正、失败重试或纯文字备用输入，不要求每题再次确认转写。

当前 DeepSeek 接口不接收音频，因此 Agent 判断的是录音经系统识别后的回答内容，而不是原始音频波形。报告不得根据转写稿推断语速、停顿、语调、音色或情绪。若将来需要这些评价，必须接入明确支持音频的模型或经过验证的声学分析服务，并重新取得用户授权；不能把没有参与分析的录音假装成评分依据。

Android 页面提供中文离线模型下载入口，但是否可用取决于系统版本、设备和已安装的语音服务。语音识别不可用、权限被拒或网络失败时，当前问题和已有文字保持不变，用户可继续键盘输入。

## 开发与测试

该功能使用自定义原生模块，Expo Go 不包含它。手机测试需要开发构建或原生构建，例如：

```bash
npx expo run:ios --device
npx expo run:android --device
```

上线前至少验证：中文普通话、长回答、短暂停顿续听、结束后自动提交、切题清空、用户修改文字、权限拒绝、无语音、弱网/断网、来电或系统中断、Android 离线模型缺失。Web 预览是否可用取决于浏览器对 Web Speech API 的支持，不能替代真机验收。

## 成本与隐私边界

代码本身和系统 API 没有按分钟的应用侧 API 费用，但这不等于所有设备都能完全离线。若设备不支持本地识别，系统服务可能联网处理音频。发布前需在隐私政策和 App Store 隐私信息中准确披露麦克风、转写文本、系统语音服务及数据保存方式。

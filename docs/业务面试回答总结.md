# AI 面试官 · 业务方面面试回答总结

> 用途：把产品真实业务口径整理成可直接口述的面试回答。  
> 口径原则：只讲当前产品已做的事；把「内测验证」和「正式商业化」分开；不确定的数字不编造。  
> 产品阶段：封闭内测。账号需人工审核；每个账号按北京时间每天只能成功启动一场新面试。

---

## 一、30 秒开场（先背这一段）

AI 面试官是给**毕业生和初入职场的人**用的模拟面试产品。用户上传并确认 PDF 简历、填写目标岗位后，系统按真实经历出题，走完整面试流程：自我介绍、简历深挖、行为面试、岗位专业题；每道主问题最多追问两次，结束后给出带回答证据的六维复盘。

我们现在不是招人工具，也不预测 Offer。当前目标是验证三件事：用户能不能把一场面试走完、问题是否贴合简历、以及他们是否愿意为这种训练付费。

---

## 二、一句话产品定位

**给求职者的、简历驱动的 AI 模拟面试与复盘工具。**

可拆成三层：

| 层次 | 说法 |
|---|---|
| 用户 | 毕业生、转岗和新入职场的求职者 |
| 动作 | 基于已确认简历和目标岗位，进行结构化模拟面试 |
| 结果 | 有限追问 + 证据型报告，帮用户把经历讲清楚，而不是给一份「像真面试官」的空评价 |

面试里如果被要求再压缩，用这句即可：

> 我们帮求职者用自己的简历练面试，而不是用通用题库刷题。

## 三、场景：谁、在什么情况下、要完成什么

场景不是「AI 很火，所以做面试」。要讲清楚使用现场。

### 标准答法

目标用户是准备校招、社招或转岗的人。他们通常已经有一份 PDF 简历，也知道自己要投的岗位，但缺少高质量对练对象：同学水平参差，培训班贵且题库泛化，真实面试机会很少、失败成本又高。

典型路径是：

1. 投递前 1–3 天，打开产品，上传并确认简历；
2. 填写目标职位，可选粘贴真实 JD；
3. 选择正式模拟（四段完整流程）或某一项专项训练；
4. 语音或文字作答；系统只根据简历和刚才的回答追问；
5. 结束后看六维报告和单题建议，回去改口述，而不是回去改一份空泛的「表达再自信一点」。

使用场景以**个人备考**为主，发生在宿舍、家里或通勤途中，不是企业面试现场。

### 场景要素表（被追问时展开）

| 要素 | 当前定义 |
|---|---|
| 谁 | 毕业生、初入职场、转岗求职者 |
| 何时 | 投递前集中准备、面试前一天复盘、收到反馈后针对性补练 |
| 何地 | 个人设备上的 Web / 后续移动端；封闭内测 |
| 为何 | 真实面试次数少、反馈晚、问题与自己的项目对不上 |
| 做什么 | 用自己的简历走一遍结构化面试，拿到可执行的复盘 |
| 不做的事 | 不替企业筛人、不预测录取、不连接招聘官网、不生成假经历 |

### 两个可口述的具体场景

**场景 A：校招正式模拟。**  
计算机专业学生下周一面某厂产品岗。他确认简历后选择正式模拟，依次练习 1 分钟自我介绍、项目深挖、STAR 行为题和岗位专业题。追问会卡在「你具体做了哪一部分」「结果怎么量化」这类缺口上，而不是随机换题。

**场景 B：转岗专项补洞。**  
运营转数据分析，专业题最虚。他不跑完整四轮，只练「岗位专业题」，用同一份简历反复讲指标口径和项目结果，降低单次负担。

## 四、背景：为什么这个需求成立

背景要回答「问题从哪来、为什么现在做、为什么是我们这种做法」。

### 标准答法

求职面试的核心矛盾不是「没有题目」，而是**题目和反馈都不够个人化**。

- 题库和模拟 App 往往按岗位标签出通用题，很难问到简历里那个具体项目；
- 真人陪练贵、难约、质量不稳定；
- 大模型对话可以聊天，但如果不约束证据来源，就会编造经历、重复提问、或给出无法执行的评价；
- 校招/社招节奏紧，用户需要的是「今晚能练完、明天能改口述」，不是一个无限聊天窗口。

所以产品选择三条硬约束：

1. **简历确认后才开问**：没有已确认简历，就不进入个性化提问；
2. **证据边界**：只根据已确认简历、用户填写的岗位/JD、以及当场提交的回答提问和评分，不编造经历；
3. **结构先于模型**：阶段顺序、追问上限、完成条件由程序决定，模型不能把一场面试拖成闲聊。

「为什么是现在」：大模型已经能围绕一段经历追问，但若没有结构化流程和证据回填，体验会回到不可控的 Chat。我们做的是把面试方法论产品化，而不是再包一层聊天框。

### 市场判断（面试里保持克制）

可以承认赛道里已有题库型、课程型和通用 Chat 型产品。我们的切入点不是「做更大的模型」，而是**求职者侧的高质量对练**：问题必须能指回简历原文，报告必须能指回用户原话。

不要在面试中声称 TAM/市场份额，除非手上有独立调研。当前阶段的诚实说法是：先在封闭内测里验证完成率和付费意愿，再决定是否放大。

## 五、目标：用户目标、产品目标、验证目标、非目标

面试官问「你们的目标是什么」时，不要只说「提高用户体验」。按四层说。

### 1. 用户目标（求职者来干什么）

把「我会做」变成「我能在面试里讲清楚」：

- 开场能在有限时间里交代岗位匹配点；
- 项目能讲清背景、个人职责、方案、问题和结果；
- 行为题能按情境把行动和结果讲完整；
- 专业题能对准目标岗位，而不是背无关知识点；
- 看完报告后知道下一句口述该改哪里。

### 2. 产品目标（产品承诺交付什么）

| 能力 | 对应承诺 |
|---|---|
| 简历驱动出题 | 问题来自已确认 PDF 简历和目标岗位，必要时带简历证据句 |
| 结构化流程 | 正式模拟四段：自我介绍 → 简历深挖 → 行为面试 → 岗位专业题 |
| 有限追问 | 每道主问题最多 2 次追问，达到上限或证据已齐就推进 |
| 专项训练 | 四段均可单独练，降低完整场次的心理和时长成本 |
| 证据型报告 | 六维：内容完整性、岗位匹配度、表达逻辑、流畅度、个人贡献清晰度、数据证据；每项有理由、原话证据和改进建议 |
| 语音优先 | 系统识别说话，文字可回看和修改；流畅度按语音节奏计算，不靠模型「听起来自信」 |

正式场次从五段收成四段，是业务决策：去掉单独的收尾轮，把有限注意力留在四类高价值考察上，降低内测完不成的概率。

### 3. 内测验证目标（现阶段真正要证明的事）

内测不是获客竞赛。每天一场、人工审核，是为了在成本可控的前提下看真实行为。

当前只验证三件事：

1. **完成**：注册并通过审核的人，能否确认简历并走完整场，而不是卡在启动、超时或中途退出；
2. **契合**：用户是否认为「问题贴合简历」「追问有深度」，而不是「问题重复」「等待太久」；
3. **付费意愿（WTP）**：面试结束后是否选择愿意付费、取决于价格、或不愿意。

这三件事分别对应漏斗完成率、反馈标签、以及 `payment_willingness`。验证的是**训练价值是否成立**，不是「能不能替企业招到人」。

### 4. 非目标（主动划边界，体现判断力）

明确不做什么，比继续加功能更像业务思考：

- 不做企业端 ATS / 笔试 / 用人决策；
- 不预测 Offer、不给录取概率；
- 不编造或润色虚假经历；
- 不为了留存取消每日一次限制去刷 DAU；
- 内测阶段不以注册量或营销投放作为第一目标。

报告页已写明：评分只用于练习反馈，不代表录用概率。面试中应主动复述这句，避免被理解成「AI 判官」。

## 六、用户价值与差异化

### 用户价值（对求职者）

一句话：**练的是自己的经历，得到的是能改的下一句，而不是一个空洞分数。**

展开三点：

1. **相关性**：问题能指到简历项目，追问针对未覆盖的目标（背景、职责、方案、问题、结果）；
2. **可控性**：阶段和追问次数有上限，一场可以在可预期时间内结束；
3. **可执行性**：报告必须引用回答证据；证据不足就标明，而不是硬打分。

### 差异化（对面试官）

对比三种常见替代方案：

| 替代方案 | 缺口 | 我们怎么处理 |
|---|---|---|
| 岗位题库 / 刷题 App | 题与个人项目脱节 | 先确认简历，再按阶段和证据出题 |
| 通用 ChatGPT 对练 | 易编造、易跑飞、难评分 | 证据边界 + 程序控制流程 + 追问上限 |
| 培训班 / 真人陪练 | 贵、难约、质量不稳定 | 随时开练；用结构化报告代替主观印象 |

差异化不是「我们有 AI」，而是 **AI 被关在面试方法论里**：该推进时推进，没证据时不评分，流畅度用语音数据而不是形容词。

### 为什么每日限额反而是产品策略

每天一场看起来像限制增长，实际服务三个业务目的：

1. **质量**：逼用户认真打完一场，而不是连开十场刷题；
2. **成本**：模型 Token 和超时重试都有成本，内测需要先看单场是否值得；
3. **信号**：在「一天只能练一次」的约束下，次日还回来，说明价值足够强。

因此限额是验证手段，不是最终商业化形态。以后若完成率和 WTP 成立，再讨论订阅次数或会员，而不是现在放开。

## 七、关键产品决策（用业务语言解释技术选择）

面试官常把产品问成功能清单。下面这些决策要用「为了什么业务结果」来答。

| 决策 | 业务理由 |
|---|---|
| 人工审核账号 | 封闭内测，控制样本质量和滥用，避免未准备好的流量冲垮模型成本 |
| 每日一场新面试 | 保证单场被认真完成，并让留存、满意度、WTP 在同一约束下可比 |
| 同一场启动可重试、不重复扣次 | 网络超时不应惩罚用户；否则完成率被基础设施噪音污染，验证会失真 |
| 未完成进度本地恢复 | 切走标签页或刷新不应导致「唯一的一次机会」作废，否则用户会把产品理解为不可靠，而不是「面试很难」 |
| 正式面试四段而非更长 | 覆盖自我介绍、项目、行为、专业题即可；过长会拉高放弃率 |
| 主问题最多两轮追问 | 模拟真实面试的追问，同时防止模型无限聊下去 |
| 报告六维且必须带证据 | 用户要的是改口述，不是被一个不可解释的总分吓到或取悦 |
| 结束后面满意度 + 付费意愿 | 把「好不好用」和「愿不愿意付钱」从聊天印象改成可统计信号 |
| 埋点不采集简历/问答/录音正文 | 内测要数据，但不能用用户最敏感的内容换数据 |

## 八、数据：用什么证明目标有没有达成

没有数据的目标是愿望。当前内测已经按周看这些指标，面试里按「指标 → 含义 → 决策」说。

### 1. 核心漏斗

`注册 → 审核通过 → 确认简历 → 启动面试 → 完成面试 → 生成报告`

重点看两段转化：

- **注册到启动**：审核、简历解析、开始按钮是否过重；
- **启动到完成**：超时、追问过长、中途退出、报告失败等体验问题。

不要把注册量当成成功。没有启动和完成，注册只说明有人想试试。

### 2. 留存

以**首次成功开始面试**为 Day 0：

- 次日是否再来面试（D1）；
- 7 天内是否复用（窗口留存）。

因为每天只有一次，回来本身就是强信号。若完成率高但次日为 0，更可能是「好奇试一次」而不是「纳入备考习惯」。

### 3. 质量与付费

面试结束收集：

- 满意度 1–5，关注 ≥4 的占比；
- 付费意愿：愿意 / 取决于价格 / 不愿意 / 暂不回答；
- 标签：问题贴合简历、追问有深度、等待太久、语音体验不顺、问题重复。

前两个正标签验证契合；后三个负标签决定下一步修体验还是修出题。  
「愿意 + 取决于价格」合计为正向付费兴趣；「不愿意」高则说明价值未讲清或价格预期不成立，不能靠加次数解决。

### 4. 成本与效率

完整一场消耗多少 Token、无效/重试请求占比。若完成率被超时拖垮，先修稳定性和幂等，再谈增长。否则会把故障当成需求。

### 口述时的纪律

- 没有当周样本就说「还在收集，不编数字」；
- 先解释指标定义，再给结论；
- 决策必须能落到产品：完成率低就减流程摩擦，负标签集中就改对应环节，WTP 低就先提高报告和追问质量。

## 九、商业化：现在不卖，但要知道怎么卖

### 当前阶段

封闭内测，免费但限频。目的是用真实使用回答：有没有人打完、觉得值不值、愿不愿意付钱。在这三件事成立前，谈定价和渠道都过早。

### 可能的付费形态（作为假设，不是承诺）

用户已经表达的是「为 AI 面试训练付费」的意愿，不是为企业招聘付费。更自然的方向是求职者订阅：

- 按月次数（例如每天一场升级为更多场次或专项不限）；
- 或按完整报告 / 针对目标岗位的训练包。

企业端招聘工具是另一条业务线，需要完全不同的客户、合规和销售，不作为内测结论的外推。

### 定价前必须先看的两件事

1. 正向付费意愿是否稳定出现在**完成面试的人**里，而不是只出现在注册未使用者里；
2. 「取决于价格」的人在听到什么价值后会转成愿意——是更多次数、更好追问，还是更可执行的报告。

如果完成的人也不愿意付费，问题在价值；如果愿意但取决于价格，问题在套餐和锚点。两者对策不同。

## 十、高频追问与推荐答法

### Q1. 你的用户是谁？为什么是他们而不是企业 HR？

我们服务求职者。他们有简历、有目标岗、缺高质量对练。企业招聘是另一类买方：要的是筛人效率和合规，不是帮候选人把项目讲顺。内测样本、反馈问题和付费问句全部围绕求职者训练，所以现阶段不讲 HR 故事。

### Q2. 需求是真的还是 AI 热点？

真需求是「面试前缺少针对我的经历的反馈」。AI 只是使个性化追问的成本下降。若只是热点，用户不会在每天仅一次的限制下还回来，也不会在结束后勾选付费意愿。我们用完成率、留存和 WTP 检验，不用下载量自证。

### Q3. 竞品那么多，壁垒在哪？

短期壁垒是工作流而不是模型：简历确认、四段结构、追问上限、证据回填、语音流畅度、内测反馈闭环。模型可替换，但这套「问什么、何时停、如何评分」不容易被一个通用聊天框复制。长期要看完成率和复用能否跑出来；跑不出来就没有壁垒可谈。

### Q4. 为什么不做成无限畅聊的面试 Copilot？

因为真实面试有时间盒。无限聊会提高 Token、降低完成率，也让报告失去可比性。我们宁可一场短而完整，也不做一场长而散。

### Q5. 成功指标是什么？北星是什么？

内测北星是**有质量的完成**：审核用户中，能够确认简历、完成面试并留下可用反馈的比例。辅助看满意度 ≥4、正向付费意愿、D1 再练。北星不是 DAU，也不是生成了多少题。

### Q6. 如果只能做一件事提升增长，你做什么？

先看漏斗断点。启动前流失，就降低简历确认和审核摩擦；启动后完不成，就修超时、恢复进度、缩短无价值轮次；完成了但不愿付费，就提高追问相关性和报告可执行性。不先投广告。内测样本小，投放只会放大尚未验证的体验问题。

### Q7. 每天一次会不会限制增长？

会限制虚假增长，这是故意的。内测要的是可解释的行为，不是被刷出来的次数。若完成率和 WTP 成立，次数会变成付费点；若它们不成立，放开次数只会让成本上升、信号更脏。

### Q8. 你们怎么避免 AI 胡编乱造？

产品层约束：简历必须用户确认；提问和评分只使用简历、JD 和已提交回答；报告缺证据就标「证据不足」；流畅度用语音节奏，不用模型形容「自信」。这是对求职场景的信任设计，不是模型参数问题。

### Q9. 下一步业务规划？

按验证顺序，不按功能愿望清单：

1. 让内测用户稳定完成一场，并收回反馈；
2. 看契合标签和 WTP 是否同向；
3. 成立后再设计求职者付费档位；
4. 不成立就先改出题、追问和报告，而不是加社交或企业版。

### Q10. 你个人在其中的业务判断是什么？

最重要的判断是：把产品定义成「帮求职者把已有经历讲清楚」，而不是「用 AI 扮演面试官」。前者可验证、可约束、可收费；后者容易做成演示，难做成对用户负责的训练工具。

## 十一、2 分钟口述稿（产品 / 业务综合面）

我做的是面向毕业生和初入职场用户的 AI 模拟面试。用户确认 PDF 简历、填写目标岗位后，按自我介绍、简历深挖、行为面试、岗位专业题四段练习，系统最多追问两次，最后给带原话证据的六维报告。

这件事成立的背景是：求职者不缺题，缺的是针对自己项目的追问和可执行反馈。通用题库太泛，纯 Chat 又容易编造和跑题。所以我们把证据边界和流程结构做成产品约束。

当前是封闭内测：人工审核，每天一场。目标不是冲量，而是验证完成、契合和付费意愿。成功不看注册数，而看有多少人打完、是否认为问题贴合简历、以及结束后是否愿意为训练付费。这些成立之前，不会把产品定义成招聘工具，也不会靠取消限额制造 DAU。

## 十二、5 分钟结构化展开（适合「请介绍你的项目」）

建议按 **背景 → 场景 → 目标 → 方案 → 取舍 → 验证 → 下一步** 说，控制在 4–5 分钟。

1. **背景（40 秒）**  
   求职准备中，真人陪练贵、题库不贴项目、通用大模型对练不可控。用户真正要的是：用我的简历，把我明天可能被问到的点练完。

2. **场景（40 秒）**  
   投递前，学生或转岗者在自己的浏览器里上传简历，选正式模拟或单项训练，语音作答，当场拿复盘。不是企业面试间，也不替代真实面试。

3. **目标（40 秒）**  
   用户目标是把经历讲清楚；产品目标是简历驱动、有限追问、证据报告；内测目标是完成率、契合度、WTP；非目标是筛人和预测 Offer。

4. **方案（60 秒）**  
   四段正式流程 + 四类专项；追问上限 2；报告六维且回填原话；语音节奏单独算流畅度。账号审核和每日一场用来控制成本和样本质量。

5. **取舍（40 秒）**  
   放弃无限畅聊、放弃企业招聘、放弃用次数堆活跃。用限额和审核换可解释的数据。正式轮次从五段收到四段，是为了提高打完的概率。

6. **验证与下一步（40 秒）**  
   周报看漏斗、D1/7 天复用、满意度、付费意愿、Token 浪费。下一步只依据断点行动：先完成，再契合，再谈定价。

## 十三、回答时的加分与避坑

**加分：**

- 先定义用户和场景，再谈模型；
- 主动讲非目标，说明你知道边界；
- 用漏斗和反馈字段说话，不把「用户觉得还行」当结论；
- 能解释「每日一次」是验证策略，不是功能简陋；
- 把技术和业务连起来：幂等重试是为了不污染完成率，证据回填是为了让报告可执行。

**避坑：**

- 不要说「我们用 AI 赋能招聘全流程」——当前没有企业客户；
- 不要报没有样本的转化率和收入；
- 不要把竞品贬成「他们没有 AI」——真实差距在工作流和证据；
- 不要把内测限额解释成「以后也永远一天一次」；
- 不要承诺预测 Offer 或保证拿 offer。
